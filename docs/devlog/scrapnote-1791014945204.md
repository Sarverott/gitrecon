## 1. Why the services needed a gateway

Pulling every image of `services/` makes a host heavier, and starting them all failed on
**ports**: on this host Coolify's own traefik (`coolify-proxy`) holds 80, 443 and 8080,
Coolify itself 8000, and the first version of the services published one localhost port
each (5432, 3306, 6379, 8123, 8888, 11435, ...) - colliding with the host and each other.

Decision: **closed by default.** Nothing publishes a port except

| Service | Published | Why |
| --- | --- | --- |
| traefik | `127.0.0.1:8880` (http), `:8843` (https), `:2222` (gitea ssh) | the gateway |
| wireguard | `0.0.0.0:51820/udp` | a VPN must be reachable |
| transmission | `0.0.0.0:51413` tcp/udp | torrent peers must be reachable |

Traefik's host ports are 8880/8843 *because* Coolify sits on 80/443 here
(`TRAEFIK_HTTP_PORT=80 TRAEFIK_HTTPS_PORT=443` on a host without another proxy - or route
`*.gr.rs-tech.online` from Coolify's proxy to `:8880`).

## 2. Main domain: gr.rs-tech.online

Persistent for routing rules, the wildcard certificate and LDAP
(`dc=gr,dc=rs-tech,dc=online`). Every web service answers on two names:

- `<name>.gr.rs-tech.online` - through the bubble, the tunnels, or a certificate later
- `<name>.localhost` - on the host itself; browsers resolve `*.localhost` to the host with
  no DNS setup at all: `http://git.localhost:8880`

## 3. How it is built

```
                    internet
                       │ (only via tunnels, only routers marked `public`)
     cloudflared ──┐   │   ┌── ngrok
                   ▼   ▼   ▼
host 127.0.0.1:8880/8843 ──► traefik 172.30.0.10 ──► <name>.gr.rs-tech.online → service
                                  ▲   entrypoints: web, websecure (default), public :8000, ssh :2222
WireGuard peer 10.13.13.x ──► wireguard 172.30.0.2 ──► project network 172.30.0.0/24
            DNS = dnsmasq 172.30.0.53:  *.gr.rs-tech.online → 172.30.0.10
                                        postgres, openldap, ... → docker DNS 127.0.0.11
                                        everything else → 1.1.1.1, 9.9.9.9
```

- **Project network** (root `compose.yaml`): `172.30.0.0/24`, fixed addresses below .128
  (traefik .10, dnsmasq .53, wireguard .2), automatic ones from `172.30.0.128/25` - so a
  container started first can never take a fixed address.
- **Traefik setup out of the command line** into `services/networking/config/traefik.yml`
  (static: entrypoints, providers, certificates); `config/traefik/dynamic.yml` is watched
  (middlewares, dashboard; Go templates: `{{ env "DOMAIN" }}`).
  - `web` and `websecure` are `asDefault`: a router with only a rule serves on both,
    HTTPS via entrypoint-level TLS - one label set per service.
  - `public` (:8000) is never published; tunnels point there; only routers naming it answer.
  - Docker provider constraint `LabelRegex(com.docker.compose.project, ^gitrecon)`: Coolify's
    containers carry traefik labels too and must not be routed by ours.
  - Certificate: Let's Encrypt wildcard by **Cloudflare DNS challenge** (`CF_DNS_API_TOKEN`) -
    no open port needed. Until the token exists, ACME errors in the log and the default cert.
- **dnsmasq** (`dockurr/dnsmasq`, rules in `config/dnsmasq/gitrecon.conf`):
  `address=/gr.rs-tech.online/172.30.0.10` and `server=//127.0.0.11` (dotless names → docker's
  DNS). Its entrypoint keeps adding upstreams (DNS1/DNS2) as long as our file has no global
  `server=` - ours only has the `//` form. `domain-needed` was dropped: it would refuse the
  dotless container names.
- **WireGuard** (linuxserver): `PEERDNS=172.30.0.53`, `ALLOWEDIPS=10.13.13.0/24,172.30.0.0/24`
  (split tunnel), NAT out of `eth+` by its default PostUp. Peer configs and QR codes in the
  `wireguard-config` drive.
- **Tunnels**: cloudflared by `CLOUDFLARE_TUNNEL_TOKEN` (public hostnames → `http://traefik:8000`
  in the Zero Trust dashboard); ngrok by `NGROK_AUTHTOKEN` + `config/ngrok.yml` (→ `traefik:8000`).
- Services announce their own HTTPS address (gitea ROOT_URL/SSH_DOMAIN, searxng, ntfy, n8n
  N8N_HOST/WEBHOOK_URL, metamcp APP_URL). Home Assistant still needs `use_x_forwarded_for` and
  `trusted_proxies: [172.30.0.0/24]` in its own `configuration.yaml`.

## 4. What was tested (a throwaway project, `gitrecon-gwtest`, own drives, wg on 51830)

- `ntfy.localhost:8880` and `Host: ntfy.gr.rs-tech.online` → 200; HTTPS on 8843 → 200;
  dashboard from the host → 200.
- `public` entrypoint from the project network: `/hooks/ping` → 200, ntfy → 404.
- dnsmasq: `*.gr.rs-tech.online` → 172.30.0.10, `ntfy`/`webhook` → their .129/.130,
  `github.com` → upstream answer.
- WireGuard: peer config has `DNS = 172.30.0.53`, the split `AllowedIPs`, endpoint
  auto-detected; server forwards and NATs.
- **Not tested:** a real peer from outside, the certificate and both tunnels (no tokens),
  gitea's SSH through traefik. The running stack was not touched.

## 7. The gists of a decade (this round)

The GitHub account dates back to 2017; its gists hold old tools still in use. Two of them sit
next to this repository now:

- `a9933eea…` - the **craftset** (`.craftset.cfg` v1.4.2.5, `mr_hefaisto.py`, `mr_lucifer.js`,
  `muscle_memory.sh` with `NOW()` = `node -e 'console.log(\`UNIXUSAT=${Date.now()}\`)'`,
  `selective_ignorance.sh`, `primer_cursting.sh`): 83 commits - the most edited gist.
- `a1d6bb15…` - **crovley** (`agent-crovley.cjs`, `armageddon.js` - Skryba's first body,
  `bos.repos.gitlist`): 49 commits.

The UNIXUSAT of this note comes from the same convention: epoch milliseconds, `Date.now()`.

New in `src/gitrecon/sources/gists.py`:

```python
gist_catalog("sarverott")               # [{gistID, filelist, description, stars, comments,
                                        #   forks, commits, size, public, created_at, url}]
clone_gists(catalog, "~/__WORKSHOP/forge/sarverott/my-gists")   # path/<gistID>, as they are
```

- GraphQL for the catalog (100 per request, needs a token): stars exist only there.
- Commits: REST `/gists/<id>/commits`. GitHub sends only `rel="next"` there - never
  `rel="last"` - so `count()` pages through (100 per page); the gist's `history` stops at 30.
- sarverott: **88 public** gists (4.2 MiB of files, 365 commits, 2 stars), **118 with the 30
  secret ones** (7.1 MiB; `--privacy all`, the owner's token only). A small gist clone is
  ~210 KB on disk (git's own files) → all of them: tens of MB.
- CLI: `gitrecon gist-catalog sarverott`, `gitrecon gist-clone sarverott <path> --dry-run`.
  Not run for real for all of them, on purpose.
