# Scrapnote: networks of relations

> 2026-10-04 · [UNIXUSAT=1791134376269] · gitrecon `development`
> A scrapnote: the first working version and where it could go. Not sorted yet.

## The spark

gitdiagram.com drew the architecture of this repository as a Mermaid flowchart (now in the
README). The same kind of picture, but of **what gitrecon looks at**: repositories, users and
organizations as a network of relations.

## What exists now

```sh
gitrecon network sarverott                          # summary: owners, who forks from whom
gitrecon network sarverott --format mermaid         # the diagram below
gitrecon network sarverott --level repos --forks-only --save   # repositories grouped by owner
gitrecon network sarverott --json                   # nodes, edges, owner overview - for a frontend
gitrecon network sarverott --format dot             # Graphviz / Gephi
```

- `mapping/network.py` - `collect_network(username)`: the user's repositories, their
  organizations and those organizations' repositories (REST listings), plus **fork parents**
  from GraphQL (the listings do not have them). Relations: `member_of`, `owned_by`, `fork_of`;
  the upstream of a fork and its owner become nodes too. Stored in the same `ActivityGraph`
  the event map uses.
- `mapping/render.py` - two zoom levels of one graph: **owners** (one node per user or
  organization, "forks from" with counts) and **repos** (grouped by owner, most connected
  first, `max_nodes`); Mermaid, DOT, JSON.
- GraphQL answers partly when an upstream sits in an organization refusing classic tokens:
  those forks come back as `null`. `graphql(partial=True)` keeps the rest. An organization
  refusing the whole query (The-Apokryf, 98 forks) gets no `fork_of` edges until a
  fine-grained token exists.

## Where it could go

More relations (each is one more edge kind in the same graph):

- [ ] **stars**: `user -starred-> repo` (2,955 for Sarverott) - then "owners I star most",
      and overlap between people: who stars the same things
- [ ] **contributors**: `user -contributes_to-> repo` (`/repos/x/contributors`) - the real
      collaboration network, beyond ownership
- [ ] **dependencies**: `repo -depends_on-> repo` from the dependency graph (SBOM API) or
      manifests of cloned repositories
- [ ] **topics and languages** as nodes: clusters by subject instead of by owner
- [ ] **links**: repositories mentioned in gists and READMEs (the link catalog already has them)
- [ ] **events**: the activity graph (`map`) and this one are the same structure - merge
      them, so a `star-burst` label can be seen on the network

What to compute on it:

- [ ] centrality: which repository or owner everything hangs on
- [ ] communities: groups that mostly connect among themselves
- [ ] paths: how two accounts are connected (shared upstream, shared organization)
- [ ] time: the network per year since 2017 - how the ecosystem grew

Where to show it:

- [ ] the docs site renders Mermaid already (this page)
- [ ] `--json` is ready for an interactive view (d3 / cytoscape) in the future `app/`
- [ ] the map dataset: a `relations` area next to `host-unions`
